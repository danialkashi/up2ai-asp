# UP2AI — وب‌سایت رسمی (ASP.NET Core 10)

سایت جذب لید برای **UP2AI — AI Systems & Business Automation**.

یک سایت مدرن ASP.NET Core 10 با معماری **MVC** و پایگاه داده **PostgreSQL** است.

## اجرا

### متطلبات
- .NET 10 SDK
- PostgreSQL 16+
- Tailwind CSS (برای build کردن CSS)

### مراحل

1. **متغیرهای محیطی** را تنظیم کن:
```bash
$env:ConnectionStrings__DefaultConnection = "Host=localhost;Port=5432;Database=up2ai;Username=up2ai;Password=up2ai;SslMode=Disable"
$env:Admin__InitialPasswordHash = "pbkdf2:210000:6641462ae51da4812a0994ab6249c9b0:0979a2f0e6946c0fd159e5f770d59861536de58b515013baec79505eec36b4a4"
```

2. **اجرا**:
```bash
dotnet run
```

سایت در `http://localhost:5065` (یا پورت دیگری) شروع می‌شود.

## رمز ورود

رمز پنل از متغیرِ محیطی `Admin__InitialPasswordHash` تنظیم می‌شود. این هش **تنها و تنها** زمانِ بوت اولیه استفاده می‌شود اگر هیچ کاربری در پایگاه داده وجود نداشته باشد.

بعد از وارد شدن:
- رمز جدید در پنل قابل تغییر است
- رمز‌های قدیمی فوری ابطال می‌شوند (تمام جلساتِ دیگر خاموش می‌شوند)
- PasswordVersion در پایگاه داده تغییر می‌کند

## معماری

| بخش | کجاست | فناوری |
|---|---|---|
| کنترل‌کننده‌ها | `src/Areas/Admin/Controllers/` | ASP.NET MVC |
| نماها | `src/Areas/Admin/Views/` | Razor |
| خانه | `src/Views/` | Razor |
| منطق داده | `src/Services/` | C# |
| پایگاه داده | PostgreSQL | JSONB |
| احراز هویت | PostgreSQL admin_users | Cookie Auth |
| CSS | `src/Styles/site.tailwind.css` | Tailwind CSS

**محتوا در هر درخواست از دیسک خوانده می‌شود** (با کشِ مبتنی بر زمان تغییر فایل)، پس هر ذخیره در پنل بلافاصله روی سایت دیده می‌شود — بدون بیلد دوباره. همان رفتار نسخه‌ی قبلی.

## پنل مدیریت — ساختار

پنل روی `/admin` است و سه بخش دارد:

| گروه | چه چیزی داخلش است |
|---|---|
| پایه‌ی سایت | هویت سایت، راه‌های تماس، منوی بالا — چیزهایی که در همه‌ی صفحه دیده می‌شوند |
| بخش‌های صفحه‌ی اصلی | محتوای هر بخش، به همان ترتیبی که بازدیدکننده اسکرول می‌کند |
| متن‌های ثابت | تیتر و توضیح بالای بخش‌ها، برچسب‌های فرم، پیام‌های خطا |

نام فارسی هر بخش و فیلد، توضیح «کجای سایت دیده می‌شود» و راهنمای زیر هر
فیلد همگی در `Services/AdminLabels.cs` جمع شده‌اند — فرم خودش از روی *شکل*
`App_Data/defaults.json` ساخته می‌شود، پس اگر فیلدی به محتوا اضافه شود
خودکار در پنل هم ظاهر می‌شود و فقط کافی است برچسب و راهنمایش را به آن فایل
اضافه کنی.

چند رفتار که عمدی‌اند و بهتر است بدانی:

- `preview`، `icon` و `from` فقط چند مقدار مشخص را می‌پذیرند (سایت بیش از
  این چند حالت را بلد نیست رسم کند)، پس در پنل **فهرست انتخابی** می‌شوند؛
  مقدارهای مجازشان در `AdminLabels.Options` و اعتبارسنجی‌شان سمت سرور است.
- `id` اصلاً در فرم نمایش داده نمی‌شود؛ فقط پنهانی رفت‌وبرگشت می‌کند و موقع
  «افزودن مورد» خودکار یکتا می‌شود (وگرنه دو تب دمو یک شناسه می‌گرفتند).
- افزودن/حذف/جابه‌جایی تا وقتی «ذخیره» نزنی روی دیسک نمی‌نشیند.
- فهرست‌هایی که پیش‌فرضشان خالی است (مثل «اعداد» در درباره ما) الگویشان در
  `AdminLabels.ListTemplateJson` تعریف می‌شود.

## ساخت دوباره‌ی CSS

فقط وقتی لازم است که کلاس تازه‌ای در `.cshtml` نوشته باشی. خروجیِ ساخته‌شده
در مخزن هست، پس اجرا و انتشار به Node نیازی ندارد:

```bash
npx @tailwindcss/cli@4 -i Styles/site.tailwind.css -o wwwroot/css/site.css --minify
```

## نکته‌ی مهم برای هاست

- باید یک پردازه‌ی .NET دائمی اجرا شود (`dotnet up2ai-asp.dll`) — هاست استاتیک کافی نیست.
- پوشه‌ی `data/` باید **ماندگار** باشد. روی هاست‌هایی که فایل‌سیستم با هر دیپلوی پاک می‌شود، یک دیسک ماندگار به همان مسیر وصل کن یا `UP2AI_DATA_DIR` را به مسیر دیسک ماندگار بده — وگرنه ویرایش‌ها و لیدها با هر انتشار می‌پرند. (یا به‌جای همه‌ی این‌ها، پستگرس؛ بخش بعد.)
- ASP.NET Core کراس‌پلتفرم است: روی لینوکس هم اجرا می‌شود (Kestrel پشت Nginx)، نیازی به سرور ویندوز نیست.
- **پنل مدیریت روی HTTPS لازم دارد.** کوکی نشست در محیط Production با پرچم `Secure` ست می‌شود، یعنی مرورگر آن را روی `http://` ساده نمی‌فرستد و ورود بی‌سروصدا کار نمی‌کند. این عمدی است (همان رفتار نسخه‌ی قبلی) — فقط یادت باشد قبل از اولین ورود، SSL دامنه را فعال کرده باشی. برای تست محلی روی HTTP، برنامه را با `ASPNETCORE_ENVIRONMENT=Development` اجرا کن.
- **Vercel از داخل ایران مسدود است** و برای .NET هم گزینه نیست؛ قبل از نهایی کردن هاست حتماً از یک اتصال ایرانی تست کن.

## ذخیره‌سازی در PostgreSQL

برنامه دو حالت دارد و انتخابش فقط با یک متغیر محیطی است:

| متغیر تنظیم نشده | متغیر تنظیم شده |
|---|---|
| همه‌چیز در `data/*.json` | همه‌چیز در پستگرس |

```bash
UP2AI_DATABASE_URL=postgres://user:pass@host:5432/dbname?sslmode=require
# نوشتار key=value هم پذیرفته می‌شود:
# UP2AI_DATABASE_URL="Host=…;Port=5432;Database=…;Username=…;Password=…;SslMode=Require"
```

`DATABASE_URL` (قرارداد رایج هاست‌های ابری) هم خوانده می‌شود.

**انتقال داده‌های موجود** — یک بار، دستی، با بکاپ در دست:

```bash
dotnet run -- migrate-to-postgres          # اگر جدول‌ها خالی باشند
dotnet run -- migrate-to-postgres --force  # حتی اگر خالی نباشند
```

فایل‌های JSON بعد از انتقال دست‌نخورده می‌مانند. اگر چیزی درست نبود، کافی است
`UP2AI_DATABASE_URL` را بردارید تا سایت دوباره از همان فایل‌ها بخواند.

نکته‌ها:

- **جدول‌ها خودکار ساخته می‌شوند** (هر بار که برنامه بالا می‌آید، با `if not exists`). ابزار مهاجرت جدا لازم نیست.
- اگر دیتابیس در دسترس نباشد، برنامه **بالا نمی‌آید** و در لاگ می‌گوید چرا — به‌جای این‌که بی‌سروصدا با سایتِ خالی سرویس بدهد.
- **پنج جدول:** `leads`, `posts`, `comments`, `admin_users`, `site_content`. هر رکورد یک سطر با ستون `doc` از نوع `jsonb` است، به‌علاوه‌ی چند **ستون تولیدشده** برای خواناییِ SQL دستی:
  ```sql
  select name, reach, business, at from leads where handled = 'false' order by at desc;
  select title, slug from posts where published = 'true';
  ```
  این ستون‌ها را خود پستگرس از `doc` می‌سازد، پس هیچ‌وقت با داده از هم عقب نمی‌افتند.
- **درایور دست‌نویس است** (`Services/Pg/PgClient.cs`) و مستقیم با پروتکل سیمیِ پستگرس حرف می‌زند — به همان دلیلی که کپچا و مارک‌داون هم دست‌نویس‌اند: این پروژه بسته‌ی بیرونی ندارد. احراز هویت SCRAM-SHA-256 و MD5، پرس‌وجوی پارامتری (بدون امکان تزریق SQL) و TLS پشتیبانی می‌شود. اگر روزی به قابلیت بیشتری نیاز شد، جای عوض کردن فقط همان یک فایل است.
- `sslmode`: `disable` | `prefer` (پیش‌فرض) | `require` (رمزگذاری بدون بررسی گواهی، مثل libpq) | `verify-full` (بررسی کامل گواهی و نام میزبان).

## تصمیم‌های فنی که ممکنه بعداً لازم بشه بدونی

**۱. چرا محتوا `JsonNode` است و نه ده‌ها کلاس C#**
شکل محتوا را `App_Data/defaults.json` تعیین می‌کند. با همین مدل، پنل مدیریت فرم ویرایش را **خودکار از روی شکل پیش‌فرض** می‌سازد — یعنی هر فیلدی که به محتوا اضافه شود، بدون دست‌زدن به کد پنل خودش آن‌جا ظاهر می‌شود. اگر کلاس‌های تایپ‌دار تعریف می‌کردیم، هر فیلد تازه باید دو جا اضافه می‌شد و پنل و محتوا خیلی زود از هم می‌افتادند. پوشش نازک `Services/Cv.cs` باعث می‌شود قالب‌ها هنوز خوانا بمانند (`@c["copy"]["hero"]["title"]`).

**۲. ادغام شکل‌محور (`Services/ShapeMerge.cs`)**
پیش‌فرض تعیین می‌کند چه چیزی *مجاز* است. هر مقداری که از `content.json` می‌آید فقط وقتی پذیرفته می‌شود که نوعش با همان جای پیش‌فرض یکی باشد؛ کلید ناشناخته یا نوع اشتباه بی‌سروصدا نادیده گرفته می‌شود. چون آن فایل را آدم هم می‌تواند دستی ویرایش کند، یک کاما‌ی جا افتاده نباید کل سایت را پایین بیاورد.

**۳. قفلِ نوشتن (`Services/JsonFileStore.cs` و `Services/Pg/PgRecordStore.cs`)**
در نسخه‌ی Node یک «صف درون‌فرآیندی» کافی بود چون همه‌ی درخواست‌ها در یک پردازه اجرا می‌شدند. ASP.NET درخواست‌ها را چندنخی اجرا می‌کند و ممکن است چند نمونه از برنامه بالا باشد، پس روی فایل **هم قفل نخی و هم قفل روی خود فایل** گذاشته شده؛ روی پستگرس همان تضمین با یک تراکنش و `LOCK TABLE … IN EXCLUSIVE MODE` گرفته می‌شود (این یکی واقعاً بین چند سرور هم کار می‌کند). بدون این‌ها، دو ارسال هم‌زمان می‌توانستند یکی از لیدها را از بین ببرند.

**۴. پنل بدون جاوااسکریپت کار می‌کند**
در نسخه‌ی ری‌اکت، مقدارِ در حال ویرایش در state مرورگر بود. این‌جا همان نقش را خودِ فیلدهای فرم بازی می‌کنند: هر ورودی به نام مسیرش در JSON نام‌گذاری شده (`f:copy.hero.title`) و طول هر فهرست در یک فیلد پنهان (`n:faq.faqs`). پس سرور در هر POST کل مقدار را دقیقاً بازمی‌سازد. نتیجه: افزودن/حذف/جابه‌جایی هم بدون جاوااسکریپت کار می‌کند، و — مثل قبل — تا وقتی «ذخیره» نزنی چیزی روی دیسک نمی‌نشیند.

**۵. تنظیم انکودر در `Program.cs`**
بدون `TextEncoderSettings(UnicodeRanges.All)`، انکودر پیش‌فرض Razor هر حرف فارسی را به `&#x…;` تبدیل می‌کند: صفحه درست دیده می‌شود ولی حجم HTML چند برابر می‌شود.

**۶. بدون هیچ پکیج NuGet**
همه‌چیز از فریم‌ورک مشترک می‌آید و `NuGet.config` منابع را خالی کرده، پس `restore` کاملاً آفلاین انجام می‌شود — روی سروری که به اینترنت آزاد دسترسی ندارد هم بیلد می‌گیرد.

**۷. CSS از بیلد Tailwind می‌آید، نه از Tailwind زنده**
`wwwroot/css/site.css` خروجی کامپایل‌شده‌ی همان Tailwind نسخه‌ی قبلی است (به‌علاوه‌ی چند قاعده‌ی انیمیشن در انتهایش). هیچ مرحله‌ی بیلد فرانت‌اند لازم نیست. اگر روزی کلاس Tailwind **تازه‌ای** خواستی که در این فایل نیست، باید یا دستی همان قاعده را ته فایل اضافه کنی یا Tailwind را روی فایل‌های `.cshtml` اجرا کنی.

**۸. رنگ‌ها**
همه‌ی رنگ‌ها توکن‌اند و در ابتدای `site.css` داخل بلاک `@theme` تعریف شده‌اند. برای تغییر پالت فقط همان بلاک را عوض کن.

**۹. حالت تیره امتحان شد و رد شد**
یک بار کل بدنه‌ی سایت تیره شد و بعد به‌خواست کاربر کاملاً برگشت. تصمیم نهایی است؛ دوباره پیشنهادش نده.

## تست

```bash
# سایت اصلی (نیاز به Node فقط برای اجرای تست، نه برای خود سایت)
node audit.mjs http://localhost:5199/
# پنل مدیریت
ADMIN_TEST_PASSWORD="…" node audit-admin.mjs http://localhost:5199
```

آخرین نتیجه‌ی این مهاجرت: صفر خطای کنسول، ۱۴۷ بررسی کنتراست بدون مردودی، صفر سرریز افقی، و پنل هم در هر چهار مسیر تمیز. متن دیده‌شده‌ی صفحه با نسخه‌ی Next.js **مو‌به‌مو یکی** است و هیچ کلاس CSS‌ای کم یا اضافه نشده.

حجم صفحه از ۲۷۵ کیلوبایت به **۹۲ کیلوبایت** و تعداد درخواست‌ها از ۱۴ به **۵** رسید، چون دیگر باندل ری‌اکت وجود ندارد.

## تغییرات اخیر

**۱. پشتیبانی از CKEditor و HTML/Markdown**
`Services/MiniMarkdown.cs` به سه متد تازه افزوده شد:
- `IsHtml()` — تشخیص فرمت محتوا (HTML یا Markdown)
- `BodyToHtml()` — تبدیل خودکار: HTML را همان‌طور برمی‌گرداند، Markdown را تبدیل می‌کند
- `BodyToPlainText()` — استخراج متن ساده: برای HTML تگ‌ها را حذف می‌کند، برای Markdown معمولی تبدیل می‌کند

کنترل‌کننده و نماهای وبلاگ برای رندرِ محتوا از این توابع استفاده می‌کنند.

**۲. رفع سرریزِ متن در کارت‌های وبلاگ**
- رشته‌های بدون فاصلا (مثل هش‌های رمز) اکنون با `word-break: break-all` شکسته می‌شوند
- کارت‌های فهرست با `overflow-hidden` و شبکه‌ی `auto-rows-max` درست شده‌اند
- کلاس `prose-content` برای محتوای وبلاگ استفاده‌شده که تمام المان‌های HTML را برای خوانایی‌ی بهتر استایل می‌کند

**۳. رفع مسیر‌های پنل مدیریت**
پنل دو صفحه ارتباطی پیدا کردند:
- `src/Areas/Admin/Views/Dashboard/Index.cshtml` — مسیرِ کارت‌های بخش اصلاح شد از `/admin/@key` به `/admin/section/@key`
- `src/Areas/Admin/Views/Section/Index.cshtml` — مسیرِ دکمه‌ی لغو اصلاح شد

**۴. دکمه‌ی بازگشت به داشبورد**
به صفحه‌ی ویرایش هر بخش (Contact, Site, Services و غیره) یک دکمه `← بازگشت به داشبورد` اضافه شد که مستقیماً به `/admin` برمی‌گردند — کنار دکمه‌های «ذخیره»، «لغو» و «بازگشت به پیش‌فرض».
