# UP2AI ASP.NET

سایت و پنل مدیریت **UP2AI** بر پایه‌ی ASP.NET Core و Razor Pages پیاده‌سازی شده است. هدف اصلی این نسخه، حفظ تجربه‌ی وب‌سایت و مدل کسب‌وکار قبلی است، اما با اجرای پایدارتر، کنترل بهتر روی داده‌ها و آماده‌سازی برای ذخیره‌سازی مطمئن‌تر در PostgreSQL.

## وضعیت فعلی پروژه

- فریم‌ورک: ASP.NET Core
- نوع اپ: Razor Pages
- پلتفرم: .NET 10
- ذخیره‌سازی عملیاتی لیدها: PostgreSQL از طریق EF Core / Npgsql
- ذخیره‌سازی JSON: دیگر مسیر عملیاتی اصلی نیست
- مهاجرت لیدها: انجام شده و در قالب Migration ثبت شده است
- ساخت و تست: با موفقیت انجام می‌شود
- وضعیت Git: کامیت‌شده و روی remote مربوطه منتشر شده است

## اجرای پروژه

```bash
dotnet restore
dotnet build
dotnet run
```

برای اجرا با URL مشخص:

```bash
dotnet run --urls http://localhost:5078
```

## تنظیم PostgreSQL

ارتباط به دیتابیس PostgreSQL از تنظیمات appsettings یا متغیر محیطی خوانده می‌شود. الگوی رایج:

```bash
$env:ConnectionStrings__DefaultConnection="Host=127.0.0.1;Port=5432;Database=up2ai_dev;Username=postgres;Password=postgres;Include Error Detail=true"
$env:UP2AI_POSTGRES_CONNECTION="Host=127.0.0.1;Port=5432;Database=up2ai_dev;Username=postgres;Password=postgres;Include Error Detail=true"
```

سپس:

```bash
dotnet run
```

> در این پروژه، دیتابیس PostgreSQL مسیر اصلی ذخیره‌سازی لیدهاست و AppDbContext مسئول دسترسی به آن است.

## معماری فعلی

| بخش | توضیح |
|---|---|
| Pages/ | صفحات Razor و UI وب‌سایت |
| Services/ | منطق کسب‌وکار، LeadStore، ContentStore و سرویس‌های مدیریتی |
| Data/ | AppDbContext و مدل‌های EF Core |
| Migrations/ | مهاجرت‌های PostgreSQL |
| App_Data/ | داده‌های پایه/پیش‌فرض |
| wwwroot/ | فایل‌های ایستا و دارایی‌ها |
| Styles/ | منابع Tailwind/استایل |

## ذخیره‌سازی لیدها

در نسخه‌ی فعلی، مسیر عملیاتی ذخیره‌سازی لیدها به PostgreSQL منتقل شده است:

- `AppDbContext` به‌عنوان کانتکست EF Core
- `LeadStore` به‌صورت Scoped ثبت می‌شود
- `DbSet<LeadEntity>` نقش اصلی را روی جدول `leads` بازی می‌کند
- JSON به‌عنوان ذخیره‌سازی اصلی حذف شده است
- Migration مربوط به PostgreSQL در مسیر `Migrations/` قرار دارد

این مدل باعث می‌شود:
- داده‌ها در یک دیتابیس سازگار و قابل‌استفاده باقی بمانند
- رفتار چندنخی و هم‌زمانی بهتر مدیریت شود
- مسیر توسعه و نگهداری پایدارتر باشد

## مهاجرت‌ها

برای اعمال/به‌روزرسانی مهاجرت‌ها از EF Core می‌توان از دستورهای معمول استفاده کرد:

```bash
dotnet ef database update
```

اگر ابزار EF Core نصب نشده باشد، ابتدا پروژه را restore و سپس ساخت را انجام دهید و در صورت نیاز ابزارها را به پروژه اضافه کنید.

## پنل مدیریت

پنل مدیریت در مسیر `/admin` قرار دارد. تنظیمات اولیه و مدیریت حساب مدیر از طریق داده‌های امنیتی و توکن‌های کوکی ASP.NET Core انجام می‌شود. هنگام راه‌اندازی اولیه، مقدار هش رمز مدیر باید به‌درستی در تنظیمات فراهم شود.

## امنیت و تنظیمات

- هیچ اعتبارنامه‌ی حساس نباید به‌صورت hardcoded در کد پروژه ذخیره شود
- مقادیر حساس باید در متغیرهای محیطی یا فایل‌های محلی غیرمنتشرقرار بگیرند
- `Admin.InitialPasswordHash` و مقادیر مشابه به‌صورت امن و خارج از کد اصلی مدیریت می‌شوند

## تست و اعتبارسنجی

```bash
dotnet build
dotnet test
```

در وضعیت فعلی، پروژه به‌صورت موفق build و test می‌شود و این وضعیت به‌عنوان مرجع برای توسعه‌ی بعدی حفظ شده است.

## نکات مهم

- پروژه با Razor Pages اجرا می‌شود و وابستگی Node برای اجرای خود سایت لازم نیست
- CSS از خروجی Tailwind/استایل پروژه استفاده می‌کند
- در مسیرهای مدیریتی، استفاده از HTTPS در محیط Production برای امنیت کوکی‌ها ضروری است
- مسیرهای فایل‌محور قدیمی برای داده‌های لید دیگر به‌عنوان مسیر اصلی استفاده نمی‌شوند

## ساختار Git

در وضعیت فعلی، تغییرات مهم مربوط به مهاجرت PostgreSQL در یک کامیت مستقل ثبت شده‌اند و پروژه در وضعیت تمیز Git قرار دارد.
